# 使用报告（周/月对比与 PPT 导出）

「使用报告」是数据看板中面向管理员的统计分节，用于回答"本周和上周、本月和上月相比，用户用了多少、用了几天、花了多少钱"这类周期对比问题。数据全部来自消费日志，无需额外采集任务；支持一键导出原生可编辑的 PPT 汇报文件。

设计文档见 `docs/superpowers/specs/2026-08-31-usage-report-ppt-design.md`。

## 权限与入口

- 仅管理员可见：普通用户登录后不会看到该分节。
- 入口：管理后台 → 数据看板 → **使用报告**。
- 数据来源：`logs` 表中类型为消费（type = 2）的记录；配置了独立日志库（LOG_DSN）时自动查询日志库，不受影响。

## 页面操作

| 操作 | 说明 |
| --- | --- |
| 周报 / 月报切换 | 周报对比本周与上周；月报对比本月与上月 |
| 周期下拉选择 | 直接选择任意历史周期（最近 26 周 / 12 个月），本期即所选周期、上期为其上一周期，例如选「2026-08」即可对比 7 月并导出；切换周/月时选项列表自动跟随 |
| 上一期 ‹ / 下一期 › | 逐期翻动周期，可回看任意历史周/月 |
| 总览卡 | 请求数、费用、Tokens、活跃用户四项总量，各带与上期的环比箭头；上期无数据时显示 "—" |
| 每日趋势图 | 本期逐天请求数（柱）与费用（线）双轴图 |
| 部门活跃统计表 | 各部门的用户总数、本期/上期活跃用户数与活跃率；活跃数带与上期的环比箭头；按活跃用户数降序排列 |
| 用户明细表 | 展示**全部注册用户**（含本期、上期均无消费记录的用户，各列为 0）；首列为**部门**，用户列优先显示「显示名称」，未设置时回退登录名；每行：请求数及环比、活跃天数（本期/上期）、费用、Tokens；按本期费用（quota）降序排列，同费用按登录名升序 |

翻期/选期仅改变页面内查询参数，不会跳转或刷新整页。

## 指标口径

- **使用频率**：以消费日志条数（即请求次数）为主要口径，Tokens 为辅助参考。
- **活跃天数**：统计周期内该用户存在消费记录的自然日天数（0–7 或 0–31）。
- **费用**：消费日志中的 quota 汇总，按系统设置的美元汇率换算展示（默认 500000 quota = $1）。
- **周期边界**：一周从周一开始（ISO 周）；月份为自然月；"某一天"的划分依据请求中的 `tz_offset` 时区，而非服务器时区，容器以 UTC 运行也不会切错天。
- **环比**：`(本期 - 上期) / 上期`；上期为 0（无消费）时不计算，显示 "—"。
- **全量用户**：用户明细表展示全部未删除注册用户（含本期/上期均无消费的用户，各列为 0），可观察从未使用或已流失的用户；已从 `users` 表删除（软删）、仅日志中存在的用户也保留，避免丢失历史数据。

## 部门属性

- 用户新增「部门」属性，后台可维护：**用户管理 → 管理部门**弹窗可增删部门清单（系统设置项 `DepartmentList`，JSON 数组）。
- 默认部门为 **公共部门**，不可删除。新建用户默认归属公共部门；存量用户在升级后由数据库列默认值自动回填为公共部门，无需手动处理。
- 用户管理页的部门列以徽标展示；编辑用户可在下拉框中选择部门。
- 使用报告中「部门活跃统计表」与用户明细表的部门列均来自该属性；无部门（或回填前）的用户归属公共部门。
- 使用报告按部门聚合活跃数：**活跃用户** = 本期存在消费记录的用户数，**环比** = 与上期活跃用户数对比，**活跃率** = 活跃用户 / 部门用户总数。

## 导出 PPT

点击页面右上角 **导出 PPT** 按钮，浏览器直接下载 `usage-report-<周期>.pptx`（周报如 `usage-report-2026-W35.pptx`，月报如 `usage-report-2026-08.pptx`）。

文件共 6 页及以上，图表与文字均为 Office/WPS 原生对象，可直接编辑：

1. 封面：报告类型、统计周期、生成时间
2. 总览对比表：四项核心指标的今/上期数值与环比
3. 部门统计表：各部门总用户、本期/上期活跃用户与活跃率
4. 每日趋势柱状图
5. 用户明细表：**全部用户**按每页 10 人分页展示（标题带页码如 `Users (2/3)`），首列为部门，不截断、无汇总行
6. 费用分布饼图：费用 Top 10 用户

PPT 文案语言跟随当前界面语言（zh 已人工翻译，其余语言键已同步、未翻译时回退英文）。

## API 调用

供脚本或二次集成直接使用，需管理员凭证（登录态或系统访问令牌，走 `Authorization: Bearer <access_token>`）。

```
GET /api/data/usage_report?period=week&anchor=2026-08-31&tz_offset=480
```

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `period` | 是 | `week` 或 `month` |
| `anchor` | 否 | 锚点日期 `YYYY-MM-DD`，默认该时区下的今天；翻页即修改此值 |
| `tz_offset` | 否 | 时区分钟偏移，东八区传 `480`；范围 `[-840, 840]`，默认 0 |

响应为项目统一封装，`data` 内结构：

```json
{
  "success": true,
  "data": {
    "period": "week",
    "current":  { "label": "2026-W35", "start_date": "2026-08-24", "end_date": "2026-08-30" },
    "previous": { "label": "2026-W34", "start_date": "2026-08-17", "end_date": "2026-08-23" },
    "overview": {
      "requests": 120, "prev_requests": 90,
      "quota": 5000000, "prev_quota": 4000000,
      "tokens": 890000, "prev_tokens": 760000,
      "active_users": 12, "prev_active_users": 10
    },
    "daily": [
      { "date": "2026-08-24", "requests": 20, "quota": 800000, "active_users": 5 }
    ],
    "departments": [
      { "department": "视频部", "total_users": 10, "active_users": 8, "prev_active_users": 4, "active_rate": 0.8 }
    ],
    "users": [
      {
        "user_id": 1, "username": "alice", "display_name": "Alice A", "department": "视频部",
        "requests": 40, "prev_requests": 25,
        "active_days": 5, "prev_active_days": 3,
        "quota": 1600000, "prev_quota": 900000,
        "tokens": 300000, "prev_tokens": 210000
      }
    ]
    // users 为全部注册用户（含本期/上期均无消费的用户，各字段为 0），按 quota 降序、同费用按 username 升序；
    // display_name 为主库显示名，未设置或已删除用户为空（展示时回退 username）；
    // department 为用户部门，无部门用户归属默认部门（展示时回退 公共部门）；
    // departments 为部门活跃聚合，按 active_users 降序：total_users 部门用户总数，
    // active_users 本期活跃用户数、prev_active_users 上期活跃用户数、active_rate = active_users / total_users
  }
}
```

参数非法（如 `period=day`、`anchor` 非 `YYYY-MM-DD`、`tz_offset` 越界）时返回 `success: false` 与错误信息；未认证返回 401。

## 部署与本地体验

前端产物内嵌进 Go 二进制，升级到包含本功能的版本后需重新构建：

```bash
make build-web     # 先产出 web/dist
go build -o new-api
```

本地体验：

```bash
make dev-api       # Docker 起 PostgreSQL + Redis + 后端（:3000）；或直接 go run main.go 使用 SQLite
make dev-web       # 前端开发服务器（:5173，代理 API 到 :3000）
```

管理员登录 → 数据看板 → 使用报告；产生消费记录后即可查看对比与导出 PPT。

## 性能与兼容性

- 查询按逐天 UTC 时间窗（`created_at >= ? AND created_at < ?`）过滤，单次报告最多发起 62 条小窗口聚合查询，不依赖任何数据库方言语法（无 `GROUP BY date()`、无日期函数），SQLite / MySQL / PostgreSQL 行为一致。
- 建议保证 `logs` 表存在 `created_at` + `type` 相关索引；日志量极大时报告仍受限于时间窗大小，不会全表扫描。
